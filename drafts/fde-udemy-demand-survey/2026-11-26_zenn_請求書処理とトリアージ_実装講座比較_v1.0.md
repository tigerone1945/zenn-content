## はじめに

現在、Udemy向けに**業務AIシステム開発を題材にしたFDE型の実践講座**を制作しています。

FDE（Forward Deployed Engineer）型の開発では、技術を実装するだけでなく、業務課題を理解し、要件を整理し、実際に利用できるシステムへ落とし込むことが重要です。

今回は、次の2つの講座を比較し、どちらへの学習需要が高いかを確認したいと考えています。

- **A：請求書処理AI**──支払前確認の業務を支援する
- **B：問い合わせトリアージAI**──問い合わせ分類・振り分けを支援する

いずれも、PythonとOpenAI Agents SDKを活用し、Streamlit＋FastAPI＋SQLiteで動くローカルPoCを構築する予定です。

## 1. 共通する開発アーキテクチャ

両講座とも、基本的なシステム構成は共通です。

```text
User
  |
  v
Streamlit
  | Web UI
  v
FastAPI
  | API / Business Logic
  v
OpenAI Agents SDK
  | AI processing
  v
SQLite
  | Local persistence
  v
Results / Review
```

この構成を利用して、Web画面、API、AI処理、データ保存の役割を整理します。

ただし、共通の技術構成を使っていても、業務に応じた設計判断は異なります。

## 2. A：請求書処理AI

### 解決したい業務課題

請求書の支払前確認では、単に請求書の情報を取り出すだけでは不十分です。

- 必須項目は揃っているか
- 業務ルールと整合しているか
- 不備や確認事項が残っていないか
- 人による確認・承認が必要か

今回の講座では、こうした業務を支援するAIシステムを題材にします。

### 想定する処理

```text
Invoice Input
    |
    v
Input Validation
    |
    v
AI Review Support
    |
    v
Business Rule Check
    |
    v
Human Review / Approval
    |
    v
SQLite
```

AIと業務ルールを組み合わせ、人が最終確認できる構成を目指します。

### 主な学習テーマ

- As-Is／To-Beによる業務分析
- 業務ルールと制約の仕様化
- AIによる確認支援
- Human-in-the-Loop
- 承認・差し戻しの状態管理
- 正常系・異常系のテスト

ポイントは、**AIが情報を理解する処理と、業務ルールに基づく判断・承認を分離すること**です。

## 3. B：問い合わせトリアージAI

### 解決したい業務課題

問い合わせ対応では、入力内容に応じて適切な処理へ振り分ける必要があります。

問い合わせの内容や確信度によって、AIが処理できるケースと、人の確認が必要なケースを分けることも重要です。

### 想定する処理

```text
Inquiry Input
    |
    v
Input Validation
    |
    v
Triage Agent
    |
    v
Classification / Routing
    |
    +--> Normal Route
    |
    +--> Human Review
    |
    v
SQLite
```

### 主な学習テーマ

- Agentの責務設計
- 分類とルーティング
- Structured Output
- Guardrails
- Human-in-the-Loop
- Tracing・テスト
- APIと画面の分離

ポイントは、**AIによる分類結果をそのまま無条件で採用せず、業務システムとして制御すること**です。

## 4. 2つの講座を比較

| 比較項目 | A：請求書処理 | B：問い合わせトリアージ |
|---|---|---|
| 主な対象業務 | 支払前確認 | 問い合わせ受付 |
| AIの主な役割 | 情報確認の支援 | 内容分類・振り分け |
| 特に学べる設計 | 業務ルール・承認状態 | Agent制御・ルーティング |
| 人の役割 | 最終確認・承認 | 判断が難しいケースの確認 |
| Webアプリ | Streamlit | Streamlit |
| API | FastAPI | FastAPI |
| AI実装 | OpenAI Agents SDK | OpenAI Agents SDK |
| データ保存 | SQLite | SQLite |

両講座とも、実装コードだけでなく、次の過程を学習対象にする方針です。

```text
Business Problem
        |
        v
As-Is / To-Be
        |
        v
System Specification
        |
        v
SDD
        |
        v
Implementation
        |
        v
Testing / Local PoC
```

## 5. 今回の講座で扱わないこと

スコープを明確にするため、今回のFDE-Udemyでは以下を対象外としています。

- Dockerによるコンテナ化
- AWS／Azure／GCPへのデプロイ
- クラウド本番運用
- Amazon Bedrock AgentCoreへの移植

まずローカルPoCの仕様・実装・テストを完結させます。

クラウド移行は、別の技術学習・講座企画として検討します。

## 6. どちらの実装を先に学びたいですか？

現在、2つの講座の制作を進めていますが、公開順序はまだ確定していません。

**AIエージェントを活用した業務システム開発を学ぶなら、どちらの題材に興味がありますか？**

- **A：請求書処理AI**──業務ルール、確認・承認、状態管理を中心に学びたい
- **B：問い合わせトリアージAI**──分類、ルーティング、Guardrails、HITLを中心に学びたい

コメント欄で **A／B／両方** のいずれかを教えていただけるとうれしいです。

さらに「この機能を実装してみたい」「この業務の難しさを知りたい」といったご意見も歓迎します。

なお、どちらのUdemy講座も現在制作中であり、公開日や教材の最終仕様は確定していません。

皆さんのご意見を、講座の公開順や演習内容の検討材料にしたいと考えています。
